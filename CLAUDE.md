# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

SpaceboatMania (MV+ Editor) is a Godot 4.6 GDScript game-authoring tool with two integrated game engines and a full in-editor content pipeline. All gameplay content is JSON-driven and authored through an integrated editor suite.

## Running

Open the project in Godot 4.6: `godot project.godot`

Entry scene: `res://Space/scenes/main.tscn`

Asset ingestion:
```bash
godot --headless --script "res://tools/import_pack.gd" -- --source <path> --pack <id>
godot --headless --import   # refresh import cache after
```

There is no test runner or CI pipeline. Validation is embedded in the editor (`content_validator.gd`). The smoke-test workflow is documented in `TESTING_GUIDE.md`.

## Agent Workflow

Project-local agent prompts live in `.claude/agents/`. The human-readable operating guide and task templates live in `.agents/`.

Use the coordinator/explorer/worker/reviewer flow for non-trivial changes: map the path first, assign bounded ownership, implement the narrow slice, validate contract behavior, run the smallest useful smoke check, then sync docs.

## Two-Engine Architecture

The project runs two separate game engines that share state through `PlanetaryInterface`:

- **Space (SSB)** — 2D spaceship combat, hex grid navigation, fleet management, procedural ships. Scripts in `Space/scripts/`, scene root `Space/scenes/main.tscn`.
- **MV (MVMania)** — Side-scroller platformer with room-based levels, tile collision, entities with behavior trees, dialogue, shops, triggers. Scripts in `MV/scripts/`, scene root `MV/scenes/main.tscn`.

Players land on planets (SSB -> MV) and launch back to space (MV -> SSB). When the ship comes in range of a landable POI, pressing `interact` (E) opens a region picker (`Space/scripts/ui/region_picker_panel.gd`, mounted by `UICoordinator.setup_region_picker`) listing the POI's `planet_data.regions[]`; choosing one calls `PlanetaryInterface.begin_landing(pack_id, poi_id, region_id, spawn_room)` and drops the player into MV at that region's spawn room. The exact spawn position inside the room comes from that room's `player_spawn` entity — regions do not carry pixel coordinates. A door with `launch_to_space: true` (or the legacy `exit_to_space` tag) routes the player back to Space. `PlanetaryInterface` is the authoritative state holder for this handoff — it manages pack staging, flag bridging, and state snapshots keyed `pack::poi_id::region_id`.

### Flag Bridge

Two namespaces in `PlanetaryInterface`:
- **Planet flags** — per-visit, snapshotted on launch, restored on re-landing. Used by triggers (`set_var`/`var_eq`).
- **Global flags** — never wiped, cross-system. Used for story/faction/credits.

Both fire `flag_changed(scope, name, old, new)`.

## Content Pack System

Content packs live under `Content/<pack-id>/` (shipped baseline, read-only) and `user://Packs/<pack-id>/` (user edits, writeable). The loader (`MV/scripts/pack_loader.gd`) tries user path first, falls back to shipped, then to `Content/demo/`.

A pack contains a `Pack.json` manifest (including `start_region`), per-region folders under `Regions/<region_id>/` (each with `region.json` + `rooms.json`, plus an optional `room_variants.json` for flag-gated room swaps), a flattened `Rooms/rooms.json` runtime view regenerated by `RegIO.flatten_to_runtime`, plus `Systems/systems.json` where POIs carry `planet_data.regions[]`. Room addresses are `<region>/<room>` or bare `<room>`; the old 3-slot `<realm>/<region>/<room>` form is rejected by the validator. See `IMPORTS.md` for the full directory layout.

## Editor Suite

The content editor (`Space/scripts/editor/content_editor.gd`) has 7 tabs: Campaign, Objects, World, Triggers, UI + FX, Audio, Playtest.

Each domain editor (entity, behavior, dialogue, trigger, environment, etc.) has a matching subdirectory under `Space/scripts/editor/` with `*_io.gd` (serialization), `*_list_panel.gd`, `*_detail_panel.gd`, and `*_topbar.gd`.

Playtest roundtrip: the environment editor stages pack/region/room in `PlanetaryInterface`, launches MV, and Ctrl+9 returns to the Space editor.

## In-Game Authoring (Console + Edit Mode)

A second authoring path runs inside the live game, separate from the desktop Editor Suite, on the `feature/in-game-authoring` branch. Everything it writes goes to the same JSON content packs (copy-on-write to the user pack).

- **Dev console** — `DevConsole` autoload (`MV/scripts/console/dev_console.gd`), toggled with backtick; one instance survives the MV↔Space scene swap and routes commands by context. MV: paste a trigger JSON (validated via `EcaSchema`, injected via `MvTriggerEngine.add_global_rule`, persisted via `PedIO`), `fire`, `spawn`. Space: `add_poi <type> <name>` (placed live + saved to `Systems/systems.json` via `SystemIO`). Shared: `flag`, `wizard <player|enemy>`, `workshop`, `help`, `clear`. An always-on corner hint advertises the console/edit keys.
- **Edit mode** — `MvEditMode` (`MV/scripts/console/edit_mode.gd`), F2 in MV. Freezes the sim; LMB/RMB paint/erase tiles or place/delete entities (Tab switches sub-mode), `P` tile palette, `Ctrl+Z` undo, `Ctrl+S` saves `tile_layers`/`collision`/`bts`/`entities` to `rooms.json`. Tile/entity mutation lives on `MvRoomManager` (`paint_cell`/`erase_cell`/`place_entity`/`remove_entity_near`/etc.).
- **Wizards** — `wizard enemy` (console Q&A → full entity def via `EntIO` + idle behavior via `BehIO`); `wizard player` (picker overlay `MvPlayerWizard` → sprite preset via `PspIO`, physics → `PhysicsProfile.tres` via `ResourceSaver`, stats/abilities via `PedIO`).
- **Combat Workshop** — `workshop` opens `MvCombatWorkshop` (`MV/scripts/console/combat_workshop.gd`), a guided 5-step enemy builder (Identity & Sprite / Stats & Combat / Behavior `WHEN→DO` rules compiled to a Beehave tree / Effects / Test & Save). Saves entity via `EntIO` + behavior via `BehIO`; **Spawn & Fight** drops a live enemy via `MvRoomManager.spawn_entity_dynamic` for a build→fight→tweak loop. (Enemy combat = behavior leaves + stat fields, distinct from the player's authored attack track below.)
- **Player Attack Workshop** — `attacks` opens `MvPlayerAttackWorkshop` (`MV/scripts/console/player_attack_workshop.gd`), the player-side companion to the enemy workshop and reachable from the latter's "Player's Attacks" track card. A 3-step builder (Attack identity / melee hitbox + combo OR projectile def / Test & Save) that authors the player's `attacks.json` (+ `projectiles.json` for ranged) via `PedIO.save_attacks`/`save_projectiles` (projectile saved first so the FK validates). **Save & Fire** calls `PlayerInventory.reload_combat_defs()` (drops the def cache, no room reload) and selects the attack so it's live immediately. Scope (honest): omits `player_pose` (no authored-pose picker → no pose override), `knockback` (player melee path doesn't apply it yet), and charge-release chains.
- **Authorable FX** — `Effects/effects.json` (`EffIO`) holds data-driven particle effects rendered by `MvAuthoredFx` and spawned by `MvFx` (built-in seed set + pack overrides). Entities carry `death_fx`/`impact_fx`; the `spawn_fx` ECA action spawns an effect by id (at coords or the event `position`). The workshop's Effects step picks or creates effects with a live preview.
- **Cross-engine** — `PlanetaryInterface.edit_session_active` flags an open authoring overlay across the scene swap.
- **Nebula skin** — the overlays are themed by `NebulaTheme` (`MV/scripts/console/nebula_theme.gd`), a cached Godot `Theme` built from the Claude Design "Nebula" handoff (`nebulous/` in the repo root): token palette consts, 9-slice armored window frames + cyan capsule buttons + recessed input slots/dropdowns, and the Robyn Brutalist Digital font. Assets live in `Assets/UI/nebula/`. The Theme is **scale-aware** — two profiles ("full" ~1×, "compact" ≥1.5×) picked from `ui_scale()`, because MV downscales its UI to 480×270 while Space is 1080p. `NebulaUi` (`nebula_ui.gd`) recreates the mockup components (work_panel, section_header, step_rail, track_card, preview_pane, variant buttons). The Combat Workshop, player wizard, and dev console are rebuilt to the mockup layouts (`nebulous/ui_kits/`): the workshop/wizard use a three-zone shell (header / StepRail / framed WorkPanels / Back·Test·Next nav) and render at **full window resolution** by flipping `content_scale_size` to 1:1 while open (restored on close); the console is the slide-up terminal with a command-chip strip; the edit-mode HUD is the top toolbar + key-hint/status pills (stays in game space). `tools/nebula_smoke.gd` proves the theme builds from real assets.

- **Pause menu + Settings + Keybindings (Nebula, cross-engine)** — `NebulaPause` autoload (`Space/scripts/ui/nebula_pause_menu.gd`, a `CanvasLayer` registered after `DevConsole`) is the canonical in-game pause overlay for BOTH engines, built from the Claude Design "Pause Menu" handoff. It owns Escape: MV (no Escape handler) opens it via `_input`, gated so it won't hijack Escape from inventory/map/dialogue/console (skips when `MvGame.simulation_paused`/`edit_session_active`/`DevConsole.visible`); Space's `_unhandled_input` Escape chain calls `NebulaPause.open()`. It branches the freeze/save/quit mechanism per engine (`MvGame.simulation_paused` + `MvSaveManager.save_game` in MV; `get_tree().paused` + Space main's `_on_pause_resumed`/`_on_quit_to_menu` + `GameManager.save_game` in Space). The card = Resume / Save Game / Settings / Exit Game + save toast + exit-confirm modal. **Settings is one Nebula screen** (`nebula_settings_screen.gd`, tabs Graphics/Audio/Gameplay/Controls) rendered generically from `Space/scripts/shared/settings/settings_catalog.gd` and driven by `SettingsManager.get_setting`/`set_setting`; it **replaces** the vanilla `settings_menu.gd` (left on disk, now unwired) and is the surface for both the pause menu and the main menu (`main_menu._open_settings_menu` → `NebulaPause.open_settings`). **Honesty:** the catalog reproduces the full handoff catalog but only `wired:true` keys drive real state (window mode/resolution, VSync, FPS cap, Master volume, UI scale via `content_scale_factor`, mute-when-unfocused, music/sfx/voice bus volumes, keybindings); every `wired:false` row shows a dim "PREVIEW — not yet wired" tag and persists value only. Keybindings (`nebula_keybindings.gd`) reuses `InputSetup.control_sections()` + the legacy capture flow; input is owned by `NebulaPause` (forwards `feed_capture` while rebinding). `tools/nebula_pause_smoke.gd` validates the catalog + that the overlays parse/construct.
- **Authored UI toggle** — the Nebula HUD/pause are canonical by default, but the wired gameplay setting **"Use authored pack UI"** (`authored_ui_path`, `settings_catalog.gd`) flips both to the per-pack authored path when on: `MvHud` (`hud.gd`) rebuilds to mount the pack's authored `hud_mv`/`hud` screen, and `NebulaPause` mounts the pack's authored `pause` screen (via `AuthoredScreenRuntime`, actions mapped onto the same resume/save/settings/exit handlers) when one exists, falling back to Nebula otherwise. Both read the setting through `SettingsManager.get_setting` and the HUD live-rebuilds on `settings_changed`.

These are hardcoded dev overlays, not authored UI, so they are intentionally NOT in `SUPPORTED_FEATURES.md` (that file is generated from `ui_contract.gd` and scoped to authored screens).

## Key Conventions

- Treat silent fallback and null-bound UI as bugs (see `ROADMAP.md` Phase 0).
- Validation failures are blockers, not warnings to ignore. `ContentValidator` runs at playtest, the editor's VALIDATE button, and the `tools/` smoke CLIs; the entity/behavior/audio/environment editors also surface full-pack issues (non-blocking) on save via `ContentValidator.validate_and_log`, and the dialogue/shop/trigger/ped editors block their own domain saves on `PedIO` validation. It is not yet a single hard gate on every save.
- The editor/runtime contract is tracked in `SUPPORTED_FEATURES.md` — if the editor exposes something not listed there, it's a bug.
- Entity AI uses the Beehave addon with leaf actions/conditions in `MV/scripts/entities/leaves/`.
- Authored screens use a universal `AuthoredScreenRuntime` that mounts into hardcoded runtime hosts (HUD, pause, inventory, etc.).
